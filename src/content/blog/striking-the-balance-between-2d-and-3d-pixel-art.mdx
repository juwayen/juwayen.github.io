## 2D or 3D engine?

I chose to emulate 2D in a 3D engine rather than the reverse, since it's much easier to hide a dimension than to fake one.

Shadows show the difference well. The standard technique in 2D pixel art games is the blob shadow, a semi-transparent dark ellipse placed beneath an object.

<figure>
	<img
		src={shadowBlobCapture.src}
		width={shadowBlobCapture.width * 4}
		height={shadowBlobCapture.height * 4}
		alt="A sprite with a blob shadow beneath it."
	/>
	<figcaption>A blob shadow. It sits under the sprite no matter where the light is.</figcaption>
</figure>

I, however, wanted shadows that respond to the light, so the next step up is the projected sprite shadow. It takes a copy of the sprite, tints it dark, and skews it across the ground plane to approximate the light direction.

<figure>
	<img
		src={shadowProjectedLowCapture.src}
		width={shadowProjectedLowCapture.width * 4}
		height={shadowProjectedLowCapture.height * 4}
		alt="A sprite with a projected shadow."
	/>
	<figcaption>A projected sprite shadow. The silhouette follows the shape of the sprite.</figcaption>
</figure>

This only holds up when the light comes from roughly in front of or behind the sprite. If the light moves to the side, the skewed copy collapses into a thin sliver.

<figure>
	<img
		src={shadowProjectedHighCapture.src}
		width={shadowProjectedHighCapture.width * 4}
		height={shadowProjectedHighCapture.height * 4}
		alt="The same sprite lit from the side."
	/>
	<figcaption>The same shadow lit from the side.</figcaption>

The engine only knows the object's silhouette from the camera's point of view, so there is no geometry for a shadow to be cast from. It's possible to extend the 2D rendering pipeline to carry volumetric data for each sprite, and use that data with raycasting to get accurate shadows, but at that point you are rebuilding a 3D renderer. It's simpler to start with one.

## Pixelation

Going 3D loses the pixel art look, so the scene needed pixelating. I had to decide between screen-space pixelation and per-object pixelation.

A standard method is to lower the internal rendering resolution and use a screen-space shader to add outlines and edges, by checking for differences in depth.

<figure>
	<img
		src={shadow3dPixelatedCapture.src}
		width={shadow3dPixelatedCapture.width * 4}
		height={shadow3dPixelatedCapture.height * 4}
		alt="A 3D scene rendered at a low resolution with a pixel art shader."
	/>
	<figcaption>The 3D scene rendered at a low internal resolution with a screen-space pixel art shader.</figcaption>
</figure>

This method loses a few things I wanted to keep from the 2D version. Namely, stable pixels, sub-texel movement, and reliable per-sprite outlines. The scene is rasterized at a low resolution every frame, so an object's pixels shift as it moves, and it can only move in whole-pixel steps.

<figure>
	<img
		src={movement2dVs3dCapture.src}
		width={movement2dVs3dCapture.width}
		height={movement2dVs3dCapture.height}
		alt="An object moving in 3D with a pixel art shader, and an object moving in 2D."
	/>
	<figcaption>Top: Object moving in 3D with a pixel art shader. Bottom: Object moving in 2D.</figcaption>
</figure>

Reliable per-sprite outlines are difficult to get in screen space, because the shader can't tell which pixel belongs to which object. An object-ID buffer can fix this, but it means juggling IDs, and the number of objects on screen is capped by the buffer's per-pixel size.

So each object has to be its own sprite, placed in the 3D scene. Hand-drawing sprites can get tedious and they carry no 3D information, so the sprites start as 3D models, and a pipeline turns them into 2D pixel sprites. I call them relief sprites.

## Pipeline

### Baking

Take a 3D model and render it with an orthographic camera at a low resolution, pointed down 45 degrees. Add a bit of lighting, which gets baked into the sprite. Also render the depth texture as an RF format .exr image.

### Rendering

Create a quad mesh and make it face the camera. The game camera must be orthographic and pointed down 45 degrees as well. A shader on the quad displays the diffuse texture, and uses changes in the depth texture to add outlines and edges.

<details style={detailsStyle}>
<summary>Shader</summary>

```gdshader
shader_type spatial;

const float ALPHA_THRESHOLD = 0.5;
const float EDGE_THRESHOLD = 0.3;
const float OUTLINE_DARKEN = 0.1;

const vec2 NEIGHBOR_OFFSETS[4] = {
	vec2(0.0, -1.0),
	vec2(0.0, 1.0),
	vec2(-1.0, 0.0),
	vec2(1.0, 0.0)
};

uniform sampler2D diffuse_texture : filter_nearest, source_color;
uniform sampler2D depth_texture : filter_nearest;

void fragment() {
	vec2 texel = 1.0 / vec2(textureSize(diffuse_texture, 0));
	
	vec4 color = texture(diffuse_texture, UV);
	float depth = texture(depth_texture, UV).x;
	
	ALBEDO = color.rgb;
	ALPHA = color.a;
	ALPHA_SCISSOR_THRESHOLD = ALPHA_THRESHOLD;
	
	float min_depth = 1.0 / 0.0; // +inf
	vec2 min_depth_uv = UV;
	
	for (int i = 0; i < 4; i++) {
		vec2 uv = UV + texel * NEIGHBOR_OFFSETS[i];
		float d = texture(depth_texture, uv).x;
		
		if (!isinf(d) && d < min_depth) {
			min_depth = d;
			min_depth_uv = uv;
		}
	}
	
	bool found_neighbor = !isinf(min_depth);
	bool is_edge = color.a < ALPHA_THRESHOLD || depth - min_depth > EDGE_THRESHOLD;
	
	if (found_neighbor && is_edge) {
		vec4 neighbor = texture(diffuse_texture, min_depth_uv);
		ALBEDO = neighbor.rgb * OUTLINE_DARKEN;
		ALPHA = 1.0;
	}
}
```

</details>

### Adding palettes

In pixel art, palettes create a consistent look. They also matter for lighting. Each material gets a ramp, a row of shades from dark to light, and the hue shifts along it. This is called hue shifting: shadows lean cooler and highlights lean warmer. Plain darkening, which is all a 3D renderer does, gives duller results.

<figure>
	<img
		src={paletteOffOnCapture.src}
		width={paletteOffOnCapture.width * 8}
		height={paletteOffOnCapture.height * 8}
		alt="A sprite without a palette next to the same sprite with a palette."
	/>
	<figcaption>Left: Sprite without a palette. Right: Sprite with a palette.</figcaption>
</figure>

The shader needs a way to tell which ramp a pixel belongs to. Give each material on the model a different albedo hue at full saturation. Shading barely changes the hue, so the hue determines the ramp and the value determines the shade within it. I used 12 hues, 30 degrees apart, far apart enough to survive the shading drift. The darkest shade of every ramp is reserved for outlines and edges. An instance uniform per hue, such as `red_material_idx`, holds the ramp's row in the palette texture. Because the sprite stores hue and value instead of final colors, palettes can also be swapped at runtime.

<figure>
	<img

		alt="A model colored by hue and the same sprite drawn with different palettes."
	/>
	<figcaption>Left: The model, with one hue per ramp. Right: The same sprite drawn with different palettes.</figcaption>
</figure>

<summary>Shader</summary>

```gdshader
// ...

global uniform int N_HUES;
global uniform int N_VALUES;
global uniform sampler2D PALETTE : source_color, filter_nearest;

instance uniform int red_material_idx = -1;
instance uniform int orange_material_idx = -1;
instance uniform int yellow_material_idx = -1;
instance uniform int lime_material_idx = -1;
instance uniform int green_material_idx = -1;
instance uniform int mint_material_idx = -1;
instance uniform int turquoise_material_idx = -1;
instance uniform int azure_material_idx = -1;
instance uniform int blue_material_idx = -1;
instance uniform int purple_material_idx = -1;
instance uniform int magenta_material_idx = -1;
instance uniform int pink_material_idx = -1;

vec3 linearToSrgb(vec3 color) {
	return mix(
		1.055 * pow(color, vec3(1.0 / 2.4)) - 0.055,
		color * 12.92,
		lessThanEqual(color, vec3(0.0031308))
	);
}

vec3 rgbToHsv(vec3 c) {
	vec4 K = vec4(0.0, -1.0 / 3.0, 2.0 / 3.0, -1.0);
	vec4 p = mix(vec4(c.bg, K.wz), vec4(c.gb, K.xy), step(c.b, c.g));
	vec4 q = mix(vec4(p.xyw, c.r), vec4(c.r, p.yzx), step(p.x, c.r));

	float d = q.x - min(q.w, q.y);
	float e = 1.0e-10;

	return vec3(abs(q.z + (q.w - q.y) / (6.0 * d + e)), d / (q.x + e), q.x);
}

vec3 paletteLookup(vec3 linear_color, bool outline) {
	vec3 hsv = rgbToHsv(linearToSrgb(linear_color));

	int hue_idx = int(round(hsv.x * float(N_HUES))) % N_HUES;
	int value_idx = 0;

	if (!outline)
		value_idx = clamp(int(round(hsv.z * float(N_VALUES))), 2, N_VALUES) - 1;

	int material_idx = {
		red_material_idx, orange_material_idx, yellow_material_idx,
		lime_material_idx, green_material_idx, mint_material_idx,
		turquoise_material_idx, azure_material_idx, blue_material_idx,
		purple_material_idx, magenta_material_idx, pink_material_idx
	}[hue_idx];

	if (material_idx == -1)
		return linear_color;

	return texelFetch(PALETTE, ivec2(value_idx, material_idx), 0).rgb;
}

void fragment() {
	// ...

	ALBEDO = paletteLookup(color.rgb, false);

	// ...

	if (found_neighbor && is_edge) {
		vec4 neighbor = texture(diffuse_texture, min_depth_uv);
		ALBEDO = paletteLookup(neighbor.rgb, true);
		ALPHA = 1.0;
	}
}
```

</details>

```gdshader
// Simplified from https://godotshaders.com/shader/texel-space-quantization/

// ...

uniform vec2 texture_size;

// ...

vec2 getScreenDelta(vec2 uv, vec2 tex_size) {
	vec2 texel_center = (floor(uv * tex_size) + 0.5) / tex_size;
	vec2 offset = texel_center - uv;
	
	mat2 screen_to_uv = mat2(dFdx(uv), dFdy(uv));
	mat2 uv_to_screen = inverse(screen_to_uv);
	
	return uv_to_screen * offset;
}

vec3 texelSnap(vec3 v, vec2 d) {
	return v + dFdx(v) * d.x + dFdy(v) * d.y;
}

void fragment() {
	// ...

	LIGHT_VERTEX = texelSnap(LIGHT_VERTEX, getScreenDelta(UV, texture_size));
}

void light() {
	DIFFUSE_LIGHT += clamp(dot(NORMAL, LIGHT), 0.0, 1.0) * round(ATTENUATION) * LIGHT_COLOR / PI;
}
```

### Adding shadow receiving

When baking, also render a displacement texture, recorded at the corner of each pixel instead of the center. The displacement is the signed distance along the camera's forward direction that a point must move from its position on the flat quad to its position in model space. Subdivide the quad to match the number of vertices and the number of pixels in the displacement texture, and move each vertex by its displacement in the vertex shader. Pad the displacement texture by one pixel to account for the outline pixels.

### Adding animations

The model is baked into a spritesheet, with one cell per animation frame and direction. Each sprite has a direction count, which determines how many directions the model is rendered from, and these form the rows. It also has an animation fps, which sets how many frames are captured per second of animation, and these form the columns. A cell's x coordinate is the animation frame, and its y coordinate is the direction the sprite faces. Because they are independent, a sprite can turn without interrupting its animation.

The shader takes two instance uniforms, `cell_x` and `cell_y`, to select the cell. Play an animation by changing `cell_x`. Set the shadow mesh to the same frame and direction so the shadows match.

```gdshader
// ...

const ivec2 CELL_SIZE = ivec2(128, 128);

// ...

instance uniform int cell_x;
instance uniform int cell_y;

vec2 cellUV(vec2 uv, vec2 sheet_size) {
	vec2 cell_offset = vec2(float(cell_x), float(cell_y)) * vec2(CELL_SIZE);
	return (uv * vec2(CELL_SIZE) + cell_offset) / sheet_size;
}

float sampleDisplacement(vec2 uv) {
	ivec2 cell_offset = ivec2(cell_x, cell_y) * (CELL_SIZE + ivec2(1));
	ivec2 corner = ivec2(round(uv * vec2(CELL_SIZE)));
	return texelFetch(displacement_texture, cell_offset + corner, 0).x;
}

void fragment() {
	vec2 sheet_size = vec2(textureSize(diffuse_texture, 0));
	vec2 sheet_uv = cellUV(UV, sheet_size);
	vec2 texel = 1.0 / sheet_size;
	
	vec4 color = texture(diffuse_texture, sheet_uv);
	float depth = texture(depth_texture, sheet_uv).x;
	
	// ...
	
	NORMAL_MAP = texture(normal_texture, sheet_uv).rgb;
}
```

</details>

## Optimizations

### Shadows

Shadow quality can be dropped to the lowest setting (Hard). This reduces anti-aliasing, which suits this technique anyway. Directional lights can use PSSM 2 Splits instead of PSSM 4 Splits (Orthogonal is too inaccurate). The hidden mesh used to cast shadows only needs vertex positions, so its UVs and normals can be stripped.

### Textures

Every sprite shares the same quad mesh and shader, so the mesh only exists once in VRAM. The textures can be cropped to remove empty space, which requires `cell_position` and `cell_size` uniforms that tell the shader where the sprite sits on the quad.

The outlines and edges can be baked into the diffuse texture, so the depth texture is no longer needed. The diffuse texture can then be reduced from 4 bytes per pixel (RGBA) to 1: one bit for alpha, since I do not need translucency, four bits for hue (I use 12), and three bits for value (I use 8).

The normal's z can be recomputed from x and y, so only those two are stored. Godot already does this. It always ignores z and recomputes it behind the scenes.

```glsl
// From the Godot source code (https://github.com/godotengine/godot/blob/4.7/drivers/gles3/shaders/scene.glsl#L2357).

// ...

#if defined(NORMAL_MAP_USED)
	normal_map.xy = normal_map.xy * 2.0 - 1.0;
	normal_map.z = sqrt(max(0.0, 1.0 - dot(normal_map.xy, normal_map.xy))); //always ignore Z, as it can be RG packed, Z may be pos/neg, etc.

// ...
```

This gives one RGB texture with the normal's x in the red channel, the normal's y in the green channel, and the diffuse byte takes the place of the normal's z in the blue channel. It can be passed directly to `NORMAL_MAP`, and must be imported without compression. The displacement texture can use half-precision floats, which halves its size with a negligible difference.

Together, these took the VRAM of an animated sprite with 65×8 cells from 122.37 MiB to 4.77 MiB, a 96.1% reduction.

## Limitations

The relief sprites only work when viewed by an orthographic camera that faces them directly.

The quad has a fixed size, so it is wasteful for small objects, and incapable of supporting objects that exceed its bounds. It is possible to overcome this by using smaller quads and tiling them.

The baking can take a long time depending on the number of animations and directions of the model. I mitigated this by writing a minimal CPU rasterizer as a Godot plugin that renders the model from plain data (vertices, UVs, etc.) instead of going through the engine. This accomplishes two things. First, it allows rendering the model at any direction and animation without having to actually mutate the model. Second, every cell is independent so the baking can be parallelized. In theory, all cells could be baked at once, but in practice it is limited by the number of CPU cores, among other things. Even so, this made things around 8 times faster.

## Conclusion

The result is a 2D pixel art style with 3D effects. Sprites have real depth, so depth of field, fog, and 3D particles work with them without extra setup. The 3D models are rendered at a low resolution, and the 2D look comes from the palette and outlines applied by the shader. This means neither pixel art skill nor detailed 3D modeling is needed to get a cohesive visual style.

```gdshader
shader_type spatial;

const vec3 ERROR_COLOR = vec3(1.0, 0.0, 0.5);

global uniform sampler2D PALETTE : source_color, filter_nearest;
global uniform ivec2 QUAD_PIXELS_SIZE; // Size of the quad mesh in pixels

uniform sampler2D data_texture : filter_nearest;
uniform sampler2D displacement_texture : filter_nearest;

uniform ivec2 cell_position;
uniform ivec2 cell_size;

instance uniform int red_material_idx = -1;
instance uniform int orange_material_idx = -1;
instance uniform int yellow_material_idx = -1;
instance uniform int lime_material_idx = -1;
instance uniform int green_material_idx = -1;
instance uniform int mint_material_idx = -1;
instance uniform int turquoise_material_idx = -1;
instance uniform int azure_material_idx = -1;
instance uniform int blue_material_idx = -1;
instance uniform int purple_material_idx = -1;
instance uniform int magenta_material_idx = -1;
instance uniform int pink_material_idx = -1;

instance uniform int cell_x;
instance uniform int cell_y;

vec2 quadUVToCellUV(vec2 model_uv) {
	vec2 uv_top_left = vec2(cell_position) / vec2(QUAD_PIXELS_SIZE);
	vec2 uv_bottom_right = (vec2(cell_position) + vec2(cell_size)) / vec2(QUAD_PIXELS_SIZE);
	
	return (model_uv - uv_top_left) / (uv_bottom_right - uv_top_left);
}

bool isCellUVOutOfBounds(vec2 cell_uv) {
	return cell_uv.x < 0.0 || cell_uv.y < 0.0 || cell_uv.x > 1.0 || cell_uv.y > 1.0;
}

vec3 sampleData(vec2 cell_uv) {
	vec2 cell_size_uv = vec2(cell_size) / vec2(textureSize(data_texture, 0));
	vec2 cell_uv_offset = vec2(float(cell_x), float(cell_y)) * cell_size_uv;
	vec2 data_uv = cell_uv * cell_size_uv + cell_uv_offset;
	
	return texture(data_texture, data_uv).rgb;
}

float sampleDisplacement(vec2 cell_uv) {
	ivec2 local_texel = ivec2(round(cell_uv * vec2(cell_size)));
	ivec2 cell_offset = ivec2(cell_x, cell_y) * (cell_size + ivec2(1));
	
	return texelFetch(displacement_texture, cell_offset + local_texel, 0).x;
}

void vertex() {
	vec2 cell_uv = quadUVToCellUV(UV);
	
	if (!isCellUVOutOfBounds(cell_uv)) {
		float displacement = sampleDisplacement(cell_uv);
		
		if (!isnan(displacement))
			VERTEX.z += displacement;
	}
}

vec3 getPaletteColor(int material_idx, int value_idx) {
	return texelFetch(PALETTE, ivec2(value_idx, material_idx), 0).rgb;
}

vec3 texelSnap(vec3 v, vec2 uv, vec2 tex_size) {
	vec2 texel_center = (floor(uv * tex_size) + 0.5) / tex_size;
	vec2 offset = texel_center - uv;
	
	mat2 screen_to_uv = mat2(dFdx(uv), dFdy(uv));
	mat2 uv_to_screen = inverse(screen_to_uv);
	
	vec2 d = uv_to_screen * offset;
	
	return v + dFdx(v) * d.x + dFdy(v) * d.y;
}

void fragment() {
	ALPHA_SCISSOR_THRESHOLD = 1.0;
	
	vec2 cell_uv = quadUVToCellUV(UV);
	LIGHT_VERTEX = texelSnap(VERTEX, cell_uv, vec2(cell_size));
	
	if (isCellUVOutOfBounds(cell_uv)) {
		discard;
	} else {
		vec3 data = sampleData(cell_uv);
		int diffuse_u8 = int(round(data.b * 255.0));
		
		int hue_idx = (diffuse_u8 >> 3) & 15;
		int value_idx = diffuse_u8 & 7;
		
		int material_idx = {
			red_material_idx, orange_material_idx, yellow_material_idx,
			lime_material_idx, green_material_idx, mint_material_idx,
			turquoise_material_idx, azure_material_idx, blue_material_idx,
			purple_material_idx, magenta_material_idx, pink_material_idx
		}[hue_idx];
		
		NORMAL_MAP = data;
		ALBEDO = material_idx == -1 ? ERROR_COLOR : getPaletteColor(material_idx, value_idx);
		ALPHA = float(diffuse_u8 >> 7);
	}
}

void light() {
	DIFFUSE_LIGHT += clamp(dot(NORMAL, LIGHT), 0.0, 1.0) * round(ATTENUATION) * LIGHT_COLOR / PI;
}
```
